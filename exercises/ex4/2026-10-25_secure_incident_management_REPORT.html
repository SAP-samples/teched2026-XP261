Committed Compiled Deployment Artifact (.mtar) Critical
A03 Software Supply Chain Failures Impact: Severe Ease: Easy Source Repository (mta_archives/)

Description

A pre-built MTA archive mta_archives/incident-management_1.0.0.mtar is committed to the source repository. Pre-built binary artifacts cannot be audited from source and may contain backdoored or tampered code that bypasses CI/CD verification. Build outputs in gen/ and app/incidents/dist/ are also committed.

Evidence

  • mta_archives/incident-management_1.0.0.mtar — compiled MTA archive at repository root
  • gen/app/incidents.zip — compiled UI5 bundle committed as build output
  • app/incidents/dist/incidents.zip — dist artifact committed to source

Attack Precondition

Attacker has repository write access. The .mtar can be silently replaced with a malicious build that executes on BTP with full application privileges.

Recommendation

  1. Remove mta_archives/ and add to .gitignore
  2. Add gen/ and dist/ to .gitignore; generate only in CI/CD
  3. Generate and sign artifacts in CI/CD (SLSA or Sigstore); verify signatures before BTP deployment
  4. Add CI check that fails if any .mtar or .zip exists outside node_modules

Credit Card Numbers Stored in Plaintext in Seed Data High
A04 Cryptographic Failures Impact: Significant Ease: Advanced Database Seed Data / Schema

Description

db/data/sap.capire.incidents-Customers.csv contains three valid-format PANs (4111111111111111, 5500000000000004, 3400000000000094) in cleartext. creditCardNo: String(16) in db/schema.cds has no encryption. @PersonalData.IsPotentiallySensitive enables audit logging only — not encryption or masking.

Evidence

  • db/data/sap.capire.incidents-Customers.csv, lines 2–4 — plaintext PANs in creditCardNo column
  • db/schema.cds, line 36 — creditCardNo: String(16) with no encryption
  • srv/data-privacy.cds, line 13 — @PersonalData.IsPotentiallySensitive (audit only)

Attack Precondition

Any actor with HANA database read access (compromised credentials, insider threat, backup media) can read PANs in cleartext without application-layer interaction.

Recommendation

  1. Replace real PANs in seed data with tokenized values (e.g., 4111-xxxx-xxxx-1111)
  2. Apply HANA column-level encryption or application-level masking to creditCardNo
  3. Store only truncated card references (last 4 digits) or payment tokens rather than full PANs

Missing HTTP Security Headers High
A02 Security Misconfiguration Impact: Moderate Ease: Easy Server Bootstrap (srv/server.js)

Description

srv/server.js does not configure any HTTP security headers. No helmet(), Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, or Strict-Transport-Security. Exposes the app to clickjacking, MIME sniffing, and weakened XSS defences.

Evidence

  • srv/server.js — cds.on('bootstrap') registers only the 403 audit handler; no security header middleware present
  • Search: grep -rn "helmet|Content-Security-Policy|X-Frame-Options" — no results across all source files

Attack Precondition

Any user accessing the application in a browser. Clickjacking requires embedding the app in an attacker-controlled iframe.

Recommendation

  1. Add app.use(require('helmet')()) in cds.on('bootstrap')
  2. Configure CSP allowing sapui5.hana.ondemand.com as script source
  3. Set X-Frame-Options: SAMEORIGIN, X-Content-Type-Options: nosniff, and HSTS
  4. Review BTP Application Router (xs-app.json) for additional header injection
4
External SAPUI5 Script Loaded Without Subresource Integrity (SRI) High
A08 Software or Data Integrity Failures Impact: Significant Ease: Advanced Frontend (app/incidents/webapp/index.html)

Description

app/incidents/webapp/index.html loads SAPUI5 from https://sapui5.hana.ondemand.com/1.138.0/resources/sap-ui-core.js without an integrity attribute. Without SRI the browser cannot verify the script has not been tampered with. CDN compromise or MitM could inject malicious JavaScript with full DOM access, potentially stealing XSUAA tokens or incident data.

Evidence

  • app/incidents/webapp/index.html, lines 12–19 — script tag without integrity or crossorigin attributes

Attack Precondition

Attacker must compromise sapui5.hana.ondemand.com CDN or perform MitM on the HTTPS connection. Version pinned to 1.138.0 reduces but does not eliminate risk.

Recommendation

  1. Add integrity="sha384-<hash>" and crossorigin="anonymous" to the SAPUI5 script tag
  2. Generate hash: openssl dgst -sha384 -binary sap-ui-core.js | openssl base64 -A
  3. Add CSP script-src directive pinning the allowed CDN origin (aligns with Finding #3)

Mocked Authentication with Hardcoded Password in Production Configuration High
A07 Authentication Failures Impact: Significant Ease: Advanced Application Configuration (package.json)

Description

package.json lines 33–40 declare auth.kind=mocked with hardcoded password "initial" for incident.support@tester.sap.com (admin role) under [development]. This file is present in deployed gen/srv/package.json. If the XSUAA binding is absent or misconfigured, CAP activates the mocked strategy granting unrestricted admin access.

Evidence

  • package.json, line 34 — "kind": "mocked"
  • package.json, line 37 — "password": "initial" for incident.support@tester.sap.com with roles: ["admin"]
  • gen/srv/package.json — mirrors the same configuration (production-deployed)

Attack Precondition

XSUAA service binding must be absent or misconfigured. Credential "initial" is visible to anyone with repository read access — no brute force required.

Recommendation

  1. Remove hardcoded password; use randomly generated test credentials in .env excluded from VCS
  2. Add runtime guard: fail fast if auth.kind === "mocked" and NODE_ENV === "production"
  3. Ensure cds.env profiles require explicit opt-in for development mode in deployed environments

No Software Composition Analysis (SCA) in CI/CD Pipeline Medium
A03 Software Supply Chain Failures Impact: Moderate Ease: Advanced Dependency Management (package.json)

Description

No SCA tooling is configured: no .snyk, dependabot.yml, renovate.json, or equivalent. All production dependencies use floating ^ version ranges. No SBOM generated. Prior overrides for qs, braces, and micromatch indicate past CVE remediation without automated tracking.

Evidence

  • package.json, lines 8–14 — all deps use ^ ranges: @sap/cds: "^10", express: "^4"
  • package.json, lines 67–70 — overrides for qs@6.16.0, braces@^3.0.3, micromatch@^4.0.8
  • Search: find . -name ".snyk" -o -name "dependabot.yml" -o -name "renovate.json" — no results

Attack Precondition

A CVE is published in a direct or transitive dependency. Without automated SCA alerting, the team is not notified. Exploitation depends on the specific CVE and reachable code path.

Recommendation

  1. Add dependabot.yml for automated dependency update PRs with security alerts
  2. Integrate OWASP Dependency-Check, Snyk, or Grype into the CI/CD build pipeline
  3. Generate SBOM during build: npm sbom --sbom-format cyclonedx
  4. Consider pinning critical production dependencies to exact versions
